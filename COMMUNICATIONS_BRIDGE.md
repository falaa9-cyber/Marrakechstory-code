# Communications bridge

The admin dashboard now renders a communications rail beside Daily agenda. It intentionally keeps provider tokens off the browser and looks for `window.MS_COMMUNICATIONS_BRIDGE`.

Implement the bridge on a trusted server or Supabase Edge Function with these methods:

```js
window.MS_COMMUNICATIONS_BRIDGE = {
  getOutlook: path => fetch(path, { credentials: 'include' }).then(r => r.json()),
  getWhatsApp: path => fetch(path, { credentials: 'include' }).then(r => r.json()),
  postOutlook: (path, body) => fetch(path, {
    method: 'POST', credentials: 'include',
    headers: { 'content-type': 'application/json' }, body: JSON.stringify(body)
  }).then(r => r.json())
};
```

## Outlook endpoints

- `GET /api/communications/outlook/inbox?top=20` → `{ connected, account, messages, folders }`
- `POST /api/communications/outlook/reply` → `{ messageId, body }`

The server should use Microsoft Graph delegated OAuth for `marrakechstory@outlook.com`, with mail read and send scopes, and keep refresh tokens encrypted server-side.

## WhatsApp endpoints

- `GET /api/communications/whatsapp/session` → `{ status, qrDataUrl, messages }`

`status` is `disconnected`, `pairing`, or `connected`. The QR must be generated by the server-side WhatsApp session and expire after pairing. The browser never receives WhatsApp credentials.
